# M5Pet

M5StickC Plus2 を「デスクの上のペット」にする Arduino スケッチです。

電源を入れると、星がまばたく夜空にリンゴが浮かび上がり → ピンクの丸いキャラクターが右から跳ねて登場 → リンゴを一口かじって → もぐもぐ噛んで → 満足そうな顔をして → 大きく口を開けて**残りを丸ごと吸い込み** → ごくんと飲み込んで → 右へ去っていく → フェードアウト → **画面いっぱいの2つの目**になります。

あとは目が勝手に生き続けます。あちこちを見回し、まばたきし、42 種類の表情を気分で切り替え、本体を傾ければそちらを見て、放っておくと少しずつ眠くなります。

## はじめてのセットアップ

M5Stack を触ったことがない人向けに、買うものからコマンドまで全部書きます。慣れている人は [書き込み方法](#書き込み方法) まで飛ばしてください。

### 1. 用意するもの

| もの | 補足 |
| --- | --- |
| **M5StickC Plus2** | 本体。秋葉原の店頭か、スイッチサイエンス／M5Stack公式で買えます。**Plus2** です（無印 M5StickC や Plus（初代）とはボード設定が違います） |
| **USB-C ケーブル** | Plus2 の端子は **USB-C** です。microUSB ではありません。**充電専用ケーブルだと書き込めない**ので、データ通信対応のものを使ってください |
| **Mac**（Windows でも可） | この手順は macOS 前提で書いています |

### 2. Arduino IDE を入れる

[arduino.cc/en/software](https://www.arduino.cc/en/software) から **Arduino IDE 2.x** をダウンロードしてインストール。

### 3. M5Stack のボードを追加する

Arduino IDE はそのままでは M5StickC Plus2 を知らないので、追加します。

1. **Arduino IDE → Settings…**（`⌘,`）を開く
2. **Additional boards manager URLs** に貼る:

   ```
   https://static-cdn.m5stack.com/resource/arduino/package_m5stack_index.json
   ```

3. OK で閉じる
4. 左のサイドバーの **Boards Manager**（基板アイコン）で `M5Stack` を検索 → **M5Stack by M5Stack official** を **Install**（数分かかります）
5. 上部のボード選択から **M5StickC Plus2** を選ぶ

### 4. ライブラリを入れる

左サイドバーの **Library Manager**（本のアイコン）で `M5Unified` を検索 → **Install**。

依存ライブラリ（M5GFX）も一緒に入れるか聞かれたら **Install All** を選んでください。

### 5. このリポジトリを持ってくる

ターミナルを開いて、そのまま貼ってください。

```bash
cd ~/Documents/Arduino
git clone https://github.com/oshiro17/M5Pet.git
```

`~/Documents/Arduino` は Arduino IDE がスケッチを探す場所（スケッチブック）です。ここに置くと IDE のメニューから開けます。

> **フォルダ名は `M5Pet` から変えないでください。**
> Arduino は「フォルダ名」と「`.ino` のファイル名」が一致していないとスケッチを開けません。`M5Pet` フォルダの中に `M5Pet.ino` がある、という状態が必須です。
> GitHub の「Download ZIP」から入れると `M5Pet-main` という名前になって**開けません**。`git clone` を使うか、展開後に `M5Pet` へリネームしてください。

### 6. 書き込む

1. 本体を USB-C ケーブルで Mac につなぐ
2. Arduino IDE で `~/Documents/Arduino/M5Pet/M5Pet.ino` を開く
3. 上部のポート選択で、`/dev/cu.usbmodem…` か `/dev/cu.wchusbserial…` を選ぶ
4. **→（Upload）**を押す

`Done uploading.` が出て、本体で星空とリンゴのアニメーションが始まれば成功です。

### つまずいたら

| 症状 | 原因と対処 |
| --- | --- |
| ポート（`/dev/cu.*`）が出てこない | ①**充電専用ケーブル**を使っている → データ通信対応のものに替える ②ハブ経由をやめて Mac に直挿し ③それでも出ないなら USB シリアルのドライバが必要（[CH9102 / CP210x](https://docs.m5stack.com/en/arduino/arduino_ide) を参照） |
| `M5Unified.h: No such file or directory` | 手順 4 のライブラリが入っていない。Library Manager で `M5Unified` を Install |
| `M5.Power` 周りでコンパイルエラー | ボードが **M5StickC Plus2** 以外になっている。手順 3-5 を確認 |
| スケッチが開けない／別ウィンドウで開く | フォルダ名が `M5Pet` になっていない（`M5Pet-main` など）。リネームする |
| 書き込み中に `Failed to connect` | ケーブルを抜き差しして、電源ボタン（左側の小さいボタン）を 6 秒長押しで一度切ってから再挑戦 |
| 画面が真っ暗のまま | バッテリーが空の可能性。USB をつないだまま数分待つ |

### 動いたら次にやること

`Config.h` を開いてください。色・レイアウト・目の動き・傾きの感度など、**見た目と手触りの調整値が全部そこに集まっています**。数値をひとつ変えて書き込み直すだけで表情が変わります。詳しくは [カスタマイズ](#カスタマイズ) を参照。

## 機能一覧

### 起動アニメーション（約 3.9 秒）

12 フェーズのタイムラインで動きます。A / B ボタンのどちらかを押すとスキップできます。

| # | フェーズ | 内容 | 長さ |
| --- | --- | --- | --- |
| 1 | `APPLE_IN` | 手つかずのリンゴがフェードイン | 300 ms |
| 2 | `ENTER` | キャラクターが右から跳ねて登場 | 520 ms |
| 3 | `APPROACH` | リンゴのそばまで寄る | 240 ms |
| 4 | `MOUTH` | 大きく口を開ける | 220 ms |
| 5 | `BITE` | *がぶっ* — かじり跡の円が広がる | 240 ms |
| 6 | `CHEW` | 3 回もぐもぐ、ほおがふくらむ | 480 ms |
| 7 | `HAPPY` | 満足そうな顔 | 220 ms |
| 8 | `INHALE_OPEN` | のけぞって口を全開にする | 260 ms |
| 9 | `INHALE` | リンゴが回りながら縮んで吸い込まれる | 520 ms |
| 10 | `GULP` | ごくん。体がふくらむ | 260 ms |
| 11 | `EXIT` | 右へ跳ねて去る | 380 ms |
| 12 | `FADE` | 暗転 | 240 ms |

- **かじり跡は画像ではなく円**：`references/apple_bitten.png` にサブピクセル精度でフィッティングした円マスクの半径を 0 → 最大にアニメーションさせているだけなので、1 枚のビットマップから「かじる前 / 途中 / 後」がすべて描けます
- **吸い込みは同じマスクを回転＋縮小変換して**口へ螺旋状に送り込みます（2 枚目の素材は不要）
- キャラクターは常に**左向きの横顔**で食べ、口の位置がかじり跡の円（画面上 152, 73）に一致するよう `Config.h` の X 座標が調整されています
- 吸い込み中は水色の吸引ラインが走ります

### 星空（`Stars`）

- 手で置いた 7 個の黄色い五芒星。位置は動かず、**その場で自転しながら、それぞれ別のクロックでまたたきます**
- シーンの明るさ（`BootAnimation::brightness()`）に連動してフェードイン／アウト
- 目の画面では既定で消えます（`STARS_ON_EYES = false` → 顔の背景は真っ黒）

### 目（`Eyes`）

**42 種類の表情**を持ちます。`EyeStyles.cpp` のテーブルに 1 行足すだけで増やせます。

| カテゴリ | 表情 |
| --- | --- |
| 基本・眠気 | `NORMAL` `SLEEPY` `HALF` `ALMOST_ASLEEP` |
| 視線固定 | `LOOK_LEFT` `LOOK_RIGHT` `LOOK_UP` `LOOK_DOWN` `LOOK_UP_LEFT` `LOOK_DOWN_RIGHT` `DARTING` |
| ポジティブ | `HAPPY` `EXCITED` `SPARKLE` `CURIOUS` `RELIEVED` `SMUG` `SHY` |
| 片目 | `WINK` `ONE_EYE_CLOSED` |
| 瞳のサイズ | `PUPIL_BIG` `PUPIL_SMALL` |
| ネガティブ・鋭い | `ANGRY` `SERIOUS`（本気） `JITO`（ジト目） `SUSPICIOUS` `TROUBLED` `SAD` `SCARED` |
| 上の空 | `THINKING` `DAZED` `VOID`（誰もいない） |
| ペア全体が動く | `PEEK_LEFT` `PEEK_DOWN_RIGHT` `TILTED`（首をかしげる） `FOCUS` `WIDE_EYED` `GLANCE_BACK` `LOPSIDED` `CROSSEYED`（寄り目） `DIZZY` |
| その他 | `SURPRISED` |

自律的な振る舞い：

- **表情の自動切り替え**：3.5〜8 秒ごとに重み付き抽選。`HAPPY` `CURIOUS` あたりが出やすく、`ANGRY` `SAD` `VOID` はまれ。「今のままでいる」枠もあるので毎回変わるわけではありません
- **サッカード（視線の跳び）**：9 方向から重み付き抽選（中央が最重）。移動距離が大きいほど移動時間が長くなりますが比例ではないので、大きく動くと「パッと飛んで落ち着く」、小さく動くと「ちょろっと」に見えます。止まっている時間は中央なら 0.7〜2.5 秒、周辺なら 0.35〜1.5 秒
- **マイクロドリフト**：数ピクセルだけのゆらぎ。常時震えるのではなく、ときどき動いて戻ります
- **まばたき**：3〜8 秒ごと。15% の確率で重く長い一回、25% の確率で 2 連続。閉じるのは速く、閉じきりは一瞬、開くのは速く始まってゆっくり収まる非対称カーブ
- **顔ごと動く**：瞳が先に動き、そのあと目のペア全体が遅れて追いつくので、視線移動が「振り向き」に見えます（`EYE_HEAD_LAG`）
- **横を見ると細くなる**：眼球が奥を向く分だけ横幅を縮めます（`EYE_SIDE_SQUASH`）
- **傾けると見る**：加速度センサ連動（下記）
- **だんだん眠くなる**：無操作 25 秒で `SLEEPY`、50 秒で `HALF`、75 秒で `ALMOST_ASLEEP` と段階的に落ちていきます

### IMU（傾き）連動

- 傾きの大きさが `IMU_TAKEOVER`（0.30）を超えると、自動の視線スケジューラから **IMU が視線の主導権を奪います**
- `IMU_RELEASE`（0.18）を下回って 1.2 秒落ち着いたら自動制御に戻ります（ヒステリシスなので境界でバタつきません）
- 視線だけでなく目のペア全体も傾けた方向へスライドします（`EYE_IMU_SLIDE_X/Y`）
- 視線を固定する表情（`LOOK_LEFT` `THINKING` など）は IMU に上書きされません

> 目が逆方向を向く場合は `Config.h` の `IMU_SIGN_X` / `IMU_SIGN_Y` の符号を反転、軸が入れ替わっている感じがする場合は `IMU_SWAP_AXES` を `true` に。

### 電源ボタンで寝かせる → シャットダウン

- 電源ボタンを**押している間、まぶたがゆっくり下りてきます**（2.5 秒で全閉）。右目がわずかに遅れて閉じます
- 途中で離せばまた開きます（閉じるより遅い速度で）
- 閉じかけの間は視線が下を向き、目の位置も落ち着いていきます
- 完全に閉じきったらバックライトを段階的に落として `M5.Power.powerOff()`

### 傾きで遊ぶブロック崩し（`Game`）

目の画面でボタン A を押すとゲームに入ります。ボールはこのキャラクター本人です。

**ゲームだけ縦画面（135 × 240）で動きます。**ペットの画面は横向きのまま作り込まれているので、ゲームに出入りするタイミングで `M5.Display.setRotation()` を切り替え、オフスクリーンバッファを作り直しています（`M5Pet.ino` の `setOrientation()`）。縦長のほうがボールがパドルに向かって走る距離が長くなり、前後傾きのスピード調整が効いてきます。

**操作は傾きだけ。**加速度センサーの 2 軸が、それぞれ別のものを 1 つずつ担当します。

#### 左右の傾き → パドル

角度をパドルの**位置**ではなく**加速度**に流し込んでいます。だから板に重さがあり、動き出しに一拍あり、傾きを戻しても惰性で滑ります。

- 中央付近は EXPO カーブで反応を鈍らせてあるので、細かい詰めが効きます（`GAME_TILT_EXPO`）
- 大きく傾けるほど速く、上限は `GAME_PAD_VMAX`（画面幅 135px に合わせて横画面時の約半分の値）
- 止まるときは指数減衰。急停止しません（`GAME_PAD_DRAG`）
- 壁に当たると少しだけ跳ね返ります

終端速度は `GAME_PAD_ACCEL / GAME_PAD_DRAG` なので、この 2 つは必ずセットで調整してください。

#### 前後の傾き → ゲームスピード

手前に倒すとスローモーション、水平で通常、奥に倒すと加速します（`GAME_TIME_MIN` 〜 `GAME_TIME_MAX`）。

変えているのは **dt だけ**で、物理式には一切触っていません。跳ね返り角も反発も速度比も、どのスピードでもまったく同じです。画面上部の細いバーが現在の倍率で、中央のノッチが通常速度。デッドゾーンがあるので「水平＝ちょうど 1.0」がきちんと出せます。

なお**パドルだけは実 dt で動きます**。スローモーションはプレイヤーに考える時間を渡すための機能なので、自分の手まで遅くなっては意味がないからです。

#### 跳ね返り

当たった位置で角度が決まり（中央＝ほぼ真上、端＝最大 60°）、そこにパドルの移動速度が少し加算されます。加算後は速度を再正規化するので、**打ち方で軌道は変わるがボールが際限なく速くなることはありません**。水平に寝てしまってラリーが終わらなくなるのを防ぐため、垂直成分の下限も入れてあります。

#### 軌跡

2 層構成です。

- **リボン** — 直近 14 フレームの位置を、縮みながら背景に溶けていく円で描画。サンプルが時間ではなく位置なので、**速いほど自動的に長くなります**。尾はピンク、頭に向かって水色〜白へ変化
- **粒子** — 星・4 方向のキラキラ・点を、速度に比例した頻度で放出。ブロックを壊したときは同じ仕組みで飛散させます

壁・ブロック・パドルに当たった瞬間は潰れます。縦の壁なら横に縮んで縦に伸び、上下なら平たく潰れる（`_squash` の符号）ので、当たった向きが見た目でわかります。

#### 難易度

面をクリアするたびに、ボール速度アップ・パドル幅ダウン・配置パターン変更（全面／市松／ピラミッド／柱／額縁の 5 種を巡回）・背景の粒密度と軌跡の太さアップ。レベル 3 から 2 回叩かないと壊れないブロックが混ざります。面の中でもブロックを壊すたび少しずつ速くなるので、最後の数個がいちばん緊張します。

残機 3。落とすと 1 減り、0 でゲームオーバー（A でリトライ、B で目の画面へ）。

### ボタン操作

| ボタン | 起動アニメ中 | 目の画面 | ゲーム中 |
| --- | --- | --- | --- |
| **A** | イントロをスキップ | **ゲームを開始** | ボールを打ち出す／ゲームオーバー時はリトライ |
| **B** | イントロをスキップ | 眠気タイマーをリセットして起こす | 目の画面に戻る |
| **電源** | — | 押している間まぶたが下りる／全閉でシャットダウン | — |

> ボタンを一切押さなくても遊べます。開始待ちは 1.8 秒で自動的に打ち出されます。

## 設計のポイント

### 表情は「コード」ではなく「データ」

`Eyes.cpp` は表情を 1 つも知りません。表情は `EyeStyles.cpp` のテーブルの行であり、追加するときも `Eyes.cpp` は一切変更不要です。

```cpp
{ "SLEEPY",
  /* L */ { .w = ..., .h = ..., .topLid = 0.55f, ... },
  /* R */ { ... },
  /* gazeX, gazeY, gazeRoam, saccadeScale, blinkScale, holdMs, ... */ }
```

テーブルと `STYLE_*` enum の長さは `static_assert` で照合しているので、**片方だけ足すとビルドエラー**になります（黙ってズレません）。

### 両目の視線は構造的に絶対ズレない

`EyeShape`（片目分のデータ）には**視線のフィールドが存在しません**。視線は `EyeStyle` 側、つまり L / R の外側にあります。したがって「うっかり左右で別の方向を向かせる」ことが型のレベルで不可能です。

形（幅・高さ・まぶた・傾き・ハイライト）は左右で好きなだけ非対称にできますが、見ている向きだけは常に共有されます。実際のフレーム合成でも、最終的な視線ベクトルは `update()` で一度だけ計算して `_gxOut` / `_gyOut` に格納し、`draw()` は両目ともそれを読むだけです（`draw()` 側で再計算させない）。

寄り目（`CROSSEYED`）も `converge` という**1 つの数値を左右に鏡像で適用**しています。左の瞳が右へ、右の瞳が同じ距離だけ左へ動く。対称かつ単一の値から導かれるので、「寄り目」になって「片目だけの斜視」にはなりません。

### すべて「現在値 / 目標値」のペアで動く

振る舞いのレイヤー（視線スケジューラ、まばたき、表情、IMU）は **目標値だけ** を書き換え、現在値が毎フレームそれを追いかけます。値が突然飛ぶことがありません。

追従の使い分けにも意図があります：

- **幅と高さはバネ**（`springTowards`）— 少し行き過ぎてから収まる。これが「びっくり」のポンという動きの正体
- **まぶた・瞳・ハイライトは指数スムージング**（`smoothTowards`）— まぶたが揺れると「生きている」ではなく「壊れている」に見えるため

### ブロッキングしない

`loop()` の中に長い `delay()` は一切ありません。`millis()` との差分でフレームを刻み、時間が来ていなければ `delay(1)` して即 return します。1 フレーム 1 回だけ画面をクリアし、オフスクリーンの `M5Canvas` に描いてから `pushSprite()` で一括転送します。

例外はシャットダウン時のバックライトフェードだけです（もうアニメーションするものが無いので許容）。
